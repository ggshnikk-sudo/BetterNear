# BetterNear

Клиентский мод для Fabric (Minecraft **26.2**): команда `/bn` **разово подсвечивает всех
игроков** в радиусе из конфига (по умолчанию **150 блоков**) на несколько секунд и выводит
список в чат. Никакой «подписки»/постоянного режима — ничего включать/выключать не нужно.

Подсветка — vanilla glow-контур (виден сквозь стены). Никаких лучей/меток на экране.
Плюс разведка игрока: пинг, броня, предметы в руках и «примерный инвентарь»
по клику на ник. Всё чисто клиентское: на сервер ничего не отправляется, другие игроки
не знают о моде.

## Команды (клиентские)

| Команда | Что делает |
|---|---|
| `/bn` | подсветить игроков в радиусе прямо сейчас (на `highlightSeconds` секунд) + список |
| `/bn info` | только список игроков в радиусе (без подсветки) |
| `/bn clear` | досрочно снять подсветку |
| `/bn radius <n>` | радиус на текущую сессию (1–5000) |
| `/bn radius` | показать текущий радиус |
| `/bn inv [игрок]` | открыть «примерный инвентарь» игрока (без аргумента — ближайший) |
| `/bn reload` | перечитать `config/betternear.json`, сбросить радиус сессии |
| `/bn status` | радиус, длительность и активна ли подсветка |

Подсветка держится `highlightSeconds` секунд (по умолчанию 5) и гаснет сама; повторный
`/bn` продлевает её. Пока подсветка активна, список пересчитывается каждый тик — новые
игроки в радиусе загораются, вышедшие гаснут. `/bn info` подсветку не трогает.

Список выводится как `• Steve — 12 m [23 ms]`.
**Ник кликабельный**: ЛКМ открывает экран разведки, наведение показывает тултип
(пинг, дистанция, броня, руки с зачарованиями).

## Экран разведки (`/bn inv`)

- Реально показываются **броня** (шлем/нагрудник/штаны/ботинки) и **руки** (main/off):
  полные `ItemStack`, в тултипе — имя и зачарования.
- **NBT/компоненты предмета по умолчанию не показываются**: на предметах с большим
  `custom_data` простыня NBT перекрывала пол-экрана. Тултип в экране разведки строится
  в обычном режиме, то есть даже включённые advanced-тултипы (`F3+H`) на него не влияют.
  Вернуть дамп можно опцией `showItemNbt` (конфиг или экран настроек).
- Остальные слоты (27 + хотбар) помечены `?` — клиенту они **недоступны**: сервер не
  отправляет содержимое чужого инвентаря. Пинг/дистанция обновляются в реальном времени,
  экран не ставит игру на паузу.

## Конфиг — `config/betternear.json`

Создаётся при первом запуске:

```json
{
  "radius": 150.0,          // радиус подсветки, блоки
  "hideInvisible": false,   // true = не подсвечивать невидимых игроков
  "hideSpectators": false,  // true = не подсвечивать спектаторов
  "showItemNbt": false,     // true = дамп NBT/компонентов в тултипе экрана разведки
  "highlightSeconds": 5.0   // сколько секунд держится подсветка после /bn
}
```

## ModMenu

Поддержка [ModMenu](https://modrinth.com/mod/modmenu): у BetterNear в списке модов есть
кнопка **«Настроить»** — экран настроек на [Cloth Config](https://modrinth.com/mod/cloth-config).

- Настраивается: радиус, длительность подсветки, «скрывать невидимых», «скрывать спектаторов»,
  «показывать NBT предмета». Кнопка «Сохранить» пишет всё в тот же `config/betternear.json`.
- И ModMenu, и Cloth Config — **мягкие** зависимости (`recommends` в `fabric.mod.json`).
  Без ModMenu всё работает как обычно; если ModMenu есть, а Cloth Config нет — кнопки
  настроек не будет (мод не падает, проверка через `FabricLoader.isModLoaded`).
- Точки входа: `"modmenu": ["gg_tv.betternear.compat.ModMenuIntegration"]`;
  класс грузится только когда ModMenu вызывает entrypoint `"modmenu"`.

## Как это устроено (26.2, Yarn)

- `EntityMixin` (`@Inject` в `Entity#isCurrentlyGlowing`) — для entity из активного набора
  принудительно возвращает `true`, поэтому `Minecraft#shouldEntityAppearGlowing` даёт
  `outlineColor` в рендере — контур рисует vanilla, видно сквозь стены. Так сделано потому,
  что на клиенте `isCurrentlyGlowing()` читает общий флаг из `SynchedEntityData`, который
  сервер перезаписывает своими пакетами (бег/присед/огонь) — выставление флага каждый тик
  мерцало. Набор активен только во время разовой подсветки (см. `BetterNearClient#tick`).
- `ClientPacketListenerMixin` — клик по нику в чате приходит как `ClickEvent.RunCommand`
  и уходит в `ClientPacketListener#sendUnattendedCommand`, который fabric-перехват
  клиентских команд не обрабатывает. Миксин ловит свои `bn inv …` и выполняет локально
  (`ci.cancel()`), на сервер ничего не уходит.
- `InventoryPeekScreen` — экран на новой рендер-модели 26.2 (`Screen#extractRenderState`
  + `GuiGraphicsExtractor`: `item`, `itemDecorations`, `blitSprite("container/slot")`,
  `setComponentTooltipForNextFrame`). `isInGameUi() = true` + `isPauseScreen() = false`.
- `PlayerInspect` — читает пинг (`ClientPacketListener#getPlayerInfo(uuid).getLatency()`),
  броню/руки (`LivingEntity#getItemBySlot`), дистанцию; дамп компонентов через
  `ItemStack#getComponents()` + `BuiltInRegistries.DATA_COMPONENT_TYPE`.
- `ClientCommands` (fabric-api client command v2) — клиентские команды `/bn …`.
- `compat/ModMenuIntegration` + `compat/ClothConfigScreen` — кнопка настроек в ModMenu;
  Cloth-код вынесен в отдельный класс, который грузится только при наличии cloth-config.
- Чистая логика без MC — `NearLogic` и `Fmt` (покрыты юнит-тестами).

Сборка: ModMenu и Cloth Config подключены как `compileOnly` (в jar не попадают).
В Loom 1.17 нет `modCompileOnly`/`modImplementation` — обычный `compileOnly` для
Fabric-мода Loom ремапит сам.

## Что проверено / не проверено

- ✅ Компиляция под Yarn 26.2 + Fabric API 0.160.0+26.2 (все имена API сверены через `javap`
  по `minecraft-merged.jar`).
- ✅ Юнит-тесты (JUnit 5): `NearLogicTest`, `FmtTest`, `BetterNearConfigTest` — 18 тестов:
  радиус/граница/фильтры, формат дистанции и цвета пинга, round-trip конфига через Gson,
  санитайз значений (диапазоны, NaN).
- ⚠️ Не покрыто автотестами (нужен живой клиент с рендером): применение миксинов в рантайме,
  отрисовка контура и экрана разведки. Паттерн миксинов совпадает с уже работающими модами
  (`bwradar`, `capecraft`). Проверяется вручную: `/bn` рядом с другим игроком, клик по нику.
- ⚠️ ModMenu-интеграция скомпилирована против установленных `modmenu-20.0.2` и
  `cloth-config-26.2.155` (сигнатуры сверены через `javap`), но кнопка «Настроить»
  на живом клиенте не проверялась (нужен запуск с ModMenu).
